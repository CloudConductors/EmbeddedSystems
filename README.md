
# 🛠️ Smart Maintenance Embedded Systems

> ⚠️ **Note:** This software requires an Arduino connected on `COM3`. It is **not** multiplatform and cannot be run without the hardware.

---

## 📌 Introduction

The **Smart Maintenance** capstone project combines **Internet of Things (IoT)** technology and **Artificial Intelligence (AI)** to analyze sensor data, predict anomalies, and schedule maintenance.  

This embedded systems component focuses on the **generation, collection, processing**, and **transmission** of data using Arduino and Raspberry Pi.

Due to the hardware-specific nature of this project, not all software can be run locally. Features like **serial communication** are tightly coupled with the Arduino microcontroller and are not easily emulated.

This README outlines the key components and logic behind the embedded systems portion.

---

## 🔄 Data Generation

Because of storage constraints on the Arduino, pre-recorded datasets couldn’t be stored directly. Instead, the Arduino generates data using **normal distribution**, simulating real-world sensor values.

🔹 **Responsibilities of the Arduino:**
- Generate component data based on good/bad dataset statistics
- Determine probability of component failure
- Transmit values as **JSON strings** over serial to the Raspberry Pi

> 📊 Mean and standard deviation values are collected beforehand using a Python script.

## 🧾 Reading Data

The **Raspberry Pi** acts as the receiver and processor. It reads incoming serial data, adds a timestamp, and prepares the data for analysis and upload.

🔹 **Process:**
1. Continuously check the serial port
2. If data is received, timestamp it
3. Prepare data for anomaly detection & AWS upload

## ☁️ AWS Integration

Once data is collected, it’s uploaded to **AWS DynamoDB** for centralized access and analysis.

🔹 **Batch Uploads:**
- Data is saved locally in a batch file
- When the batch reaches a set size, it’s sent to DynamoDB using AWS's batch write feature

🔹 **Anomaly Override:**
- If an anomaly is detected, the batching process is bypassed
- The entire batch is uploaded immediately for real-time updates

## 🚨 Anomaly Detection

After receiving new data, the Raspberry Pi runs an **anomaly detection ML model** to evaluate component health.

🔹 **How it works:**
- ML model is downloaded from an AWS S3 bucket at launch
- If an anomaly is detected:
  1. The maintenance schedule table on DynamoDB is updated
  2. Data is uploaded immediately, ignoring batch thresholds

## 🌐 Network Outage Caching

To maintain **data integrity** during network disruptions, a caching system was implemented.

🔹 **Offline Behavior:**
- If the network is down when downloading the ML model, a local copy is used
- Collected data is cached in batch files
- Anomaly detection is deferred until the network is restored

🔹 **When Back Online:**
- Cached data is processed by the ML model
- Detected anomalies are reported and sent to AWS
